# Production database baseline

Read-only snapshot of the production `public` schema for project `pqpnwxyevrsipklzmwex`, captured on 2026-08-08.

## Important

- This directory is documentation and recovery inventory, not an executable migration.
- Do not move these files into `supabase/migrations` or apply them to a database.
- No table rows, customer records, authentication records, or stored secrets are included.
- Managed schemas such as `auth`, `storage`, `realtime`, `vault`, and extension-owned schemas are excluded.

## Contents

- `database.types.ts`: application-facing TypeScript types generated by Supabase.
- `public-tables.json`: tables, columns, primary keys, foreign keys, and RLS state.
- `routines.json`: public function/procedure definitions and security-definer flags.
- `policies.json`: row-level security policies.
- `triggers.json`: non-internal triggers.
- `indexes.json`: public-schema indexes.
- `grants.json`: explicit table and routine grants.
- `migration-history.json`: migration history reported by the production project.
- `manifest.json`: capture metadata and object counts.

## Refresh procedure

Regenerate every file from the same production project using read-only Supabase catalog access. Review the diff for secrets and unexpected privilege changes before committing. A future canonical SQL dump should be produced with the official Supabase CLI after project linking and database credentials are available; keep that dump outside `supabase/migrations` unless it is intentionally converted into reviewed migrations.
